# 技术交接文档

## 0. 基本信息
- **轻应用标题**: 时间块
- **核心价值**: 精细时间块视图与高效记录
- **说明**: 本文件为兜底技术交接稿；实现阶段必须优先结合 `design.md` 补齐能力、状态、数据和降级判断。

## 1. 主模块与职责划分
- **页面模块**: 以 `design.md` 的页面清单和核心页面详细设计为准。
- **状态模块**: 实现前从 `design.md` 的核心功能、状态和页面动作中拆分页面本地态与跨页面共享态。
- **数据模块**: 实现前根据 `design.md` 的能力列表、核心能力真实性检查和资产映射判断是否需要本地持久化、服务化能力或 DB。

- **边界原则**: 不得新增 `design.md` 未纳入首版的扩展功能，也不得遗漏 `design.md` 已纳入首版的核心功能、支撑 / 扩展功能、页面、状态或恢复动作；不得用 mock、假按钮、假进度或静态占位承载核心能力。

## 2. Runtime / API 能力策略
- **能力总表**: 以 `design.md` 的 `能力列表`、核心功能和数据真实性契约共同确定；能力列表为空时先确认没有任何核心动作依赖运行时数据、媒体、AI、服务化或持久化能力，只有三者一致时才实现纯前端闭环或本地页面态；若核心动作与能力列表冲突，必须把它标为交接不一致，不能保留动作却用静态样例、外部查阅提示或假成功取消必需能力。
- **角色 / 端 / 权限策略**: 以 `design.md` 的角色、数据范围和本人状态契约为准；需要查看“我的记录 / 我的号码 / 我的提交状态”时沿用其中已确定的稳定业务身份、可持久化创建结果绑定或个人状态，不在兜底技术交接中重新拆分数据对象；本地缓存不能成为唯一身份凭证。
- **核心能力真实性检查**: 逐条核对 `design.md` 核心功能，确保真实输入、真实处理、真实输出和可见反馈都落地。
- **能力选择理由与边界**: 逐条核对 `design.md` 能力列表中的能力是否服务已纳入首版的核心功能、支撑功能或扩展功能，并写清为什么选择该能力、相近能力为什么不选；涉及公开数据时区分前端运行时检索和服务化检索，涉及服务化时必须有真实 runtime 承接，禁止只生成自定义 endpoint 占位。
- **数据真实性与覆盖契约**: 若 `design.md` 已包含数据契约，按其执行；若缺失，必须实现前补判数据类型：实时数据需要运行时检索，公开目录需要按当前条件检索 / 查询，稳定知识只有在体量小且完整来源已验证时才可完整预置，开放知识问题需要搜索入口，多人共享状态需要服务化 / DB，媒体 / AI 转换需要真实能力返回结果。范围稳定但体量较大或完整性无法验证的正文、题库、图鉴、法规等内容，如果条目仍可阅读、练习、查阅或计入进度，必须采用目录 / 元数据种子 + 单篇 / 单条按需检索 + 缓存 + loading / empty / error / retry；若当前能力确实不能按需获取，只能把正常使用和进度范围收敛到本地已有完整内容，缺内容条目不得伪装成可正常完成。
- **数据持久化 / 服务化 / DB 判断**: 单份轻量键值状态、简单偏好、主题设置或单份游戏进度可本地持久化；多条记录、会随使用增长的列表、按条增删改查、条件查询 / 分页、用户隔离、共享状态、权限管理、服务端聚合或跨设备一致性应评估服务化能力或 DB，不能塞进一个本地 key 做全量读写。
- **服务化 / DB 落地契约**: 若 `design.md` 的能力、角色或数据契约包含服务化能力、DB 或 `multi_user_state`，实现前必须列出由真实运行时链路承载的核心动作、共享 / 隔离结果、成功 / 空态 / 失败反馈，并写清每类共享数据谁创建、谁可读、谁可更新、普通用户之间是否互相可见、如何定位自己的记录；DB 不等于必然前后端分离，具体由前端直连 DB 还是服务端 controller 承载，交给实现阶段依据可用 runtime 与开关判断；禁止只生成协议占位、前端本地假同步、静态管理页或没有真实运行时处理的核心链路。
- **需要的 API / 运行时能力**: 以 `design.md` 明确列出的能力名为起点，并与既有核心功能和数据真实性契约校验一致；只能补回已有核心动作必然需要且平台可用的能力，不能借此新增产品范围。
- **结构化返回与归一化契约**: 若能力链路包含搜索、AI、媒体识别、DB 查询或服务返回，必须实现前补齐目标业务对象、关键字段、字段缺失 UI 策略和返回载荷归一化要求；实现阶段应按能力文档确认返回形态，再提取正文或结构化字段。列表结果进入页面渲染前必须归一化为业务数组或业务对象；不能把未知返回值直接当字符串或业务对象解析。
- **核心链路验收契约**: 按 `design.md` 的核心功能逐条补齐触发动作、必需成功条件、失败 / 不可用条件和不允许的假成功；不能把空数组、空对象、静态样例、永久 loading、只更新 UI 未保存、字段缺失仍进入下游流程、异常返回导致白屏或空 DOM 等当作核心成功。
- **核心业务对象 / ViewModel 契约**: 若核心链路会渲染或保存列表、卡片、题目、资料、记录、推荐、行程、统计或作品，实现前必须定义页面最终消费的业务对象、required 字段、字段缺失 UI 策略、内部 id/key 与中文 label 分离规则，以及进入下游流程的最小完整性；不写平台原始返回字段。
- **查询 / 筛选字段契约**: 若核心链路包含领域实体、分类枚举、地点、公开对象、服务或内容类目等筛选或搜索条件，必须补齐字段所属业务主体、internalKey、displayLabel、queryAlias / searchLabel、返回字段和 normalize 后字段；人员属性、房间约束、对象属性和用户身份不得相互替代，公开搜索 query 使用用户可读 label 或别名，本地过滤前先把返回 label / alias 归一化。
- **能力返回归一化契约**: 搜索、AI、媒体识别或服务能力必须按“原始返回 -> 规范业务对象 -> 页面编辑对象 / 渲染对象”转换；实现阶段先查能力文档确认真实载荷，再映射到业务对象，解析失败必须进入错误 / 可编辑 fallback，不能静默保存空对象或把空数组当成功。
- **事实类 AI 上下文契约**: 若 AI 对公开事实、新闻、搜索结果、用户上传内容或长文档做解读 / 总结 / 推荐，必须写清传给 AI 的来源、时间、正文 / 摘要边界、原始条目、用户输入和检索证据；只有短标题、短 snippet 或模型常识时，必须先补充检索 / 获取详情 / 让用户补充材料，或把输出标注为低置信参考。
- **媒体输入落地契约**: 若上传、拍照、截图、扫描或创建媒体 / 业务对象是核心输入，必须让实际对象或忠实预览可见、可替换，并把用户确认后的业务字段映射到页面可编辑对象和后续保存 / 计算对象；正常成功态不能只显示“已拍摄 / 已创建 / 已完成”等通用文本占位，只有原始需求明确要求延迟揭示或隐私遮挡时才允许占位并写清解除条件。只有 应用设计 明确要求识别、扫描、解析、OCR 或 VLLM 时，才必须调用真实识别能力。仅保存媒体 URL、静态示例或不可编辑字段，不等价于完成媒体输入链路。
- **角色 / 权限来源契约**: 若应用包含创建者 / 被分享者、管理员 / 普通用户、提交人 / 查看人、房主 / 参与者等角色分工，必须写清角色来源、首次进入分流和不能手动切换权限的边界；首屏自选角色只适用于普通业务偏好或非权限身份。
- **共享状态权威源契约**: 排队号、库存、名额、报名人数、点赞数、成员列表、共享进度、全局序号等多人共同推进的状态，必须有单一 source of truth、唯一性 / 容量等业务不变量、当前能力真实支持的原子写入或冲突保护、重复提交反馈和写入后重新读取策略；查询当前数量后加一、前端先读后写或能力文档不支持的 DB 表达式都不能作为正确实现方案。
- **生成阶段能力策略**: 只列 `design.md` 中需要实际调用的生成阶段任务。每个 asset_id 只选一个 primary capability，并把“真实 API 参数”和“实现交接信息”分栏表达。`source=IMAGE_SEARCH(real_source)` 的 CapabilityCall 只写 `capability=asset.image_search + query + limit`；另写 `asset_id + visual_role + placement + integration_mode + selection_criteria + 目标比例 + 实现落点`，这些用于 Coding 选图、布局和资源映射，不得作为图搜参数传入。失去图片会破坏默认首屏、核心结果或既定构图时，必须声明 `fallback_capability=asset.image_generate + fallback_prompt + width / height + asset_mode + fallback_result`；Coding 调用时把 fallback_prompt 作为 `prompt` 传入，并且仅在图片搜索返回 `has_usable_asset=false` 后最多调用一次，不编排换词重试。可选对象图可以改为信息优先缺图态。ImageGen fallback 只能生成风格化插画、概念场景、剪影、氛围背景或纹理，不得冒充真实照片、真实外观或事实证据。`source=generated_image` 的 CapabilityCall 只写 `capability=asset.image_generate + prompt + width / height + asset_mode`；另写 asset_id、视觉职责、落点、实现路径，以及 `has_usable_asset=false` 时不重复生图的结构降级。背景 / 场景任务把 `design.md` 的主体与保护范围、HTML 低细节信息区、明暗路径、surface 衔接边缘、裁切边界和禁止烘焙内容直接写入 prompt；生成尺寸必须匹配主承载槽位，完整场景用 `opaque_image`，透明前景用 `transparent_asset`，仅四边无缝且实际平铺的纹理用 `tileable_texture`；若有预置音频同样列出生成任务；均无则写 无。
- **视觉资产实现计划**: 按 `design.md` 的 asset_id 简要转写 `source + capability + visual_role + placement + integration_mode + 导入 / 输出路径 + 实际 CSS 比例 + object-fit / object-position + 复用位置`，不重复艺术方向和来源论证。对背景主导资产额外转写 `canvas_scope + 图层顺序 / overlay + HTML 信息区 + surface 衔接 + 色彩 / 材质继承`；默认常态 / 高频资产必须保留原落点，背景不得缩进卡片或被不透明通用 surface 遮掉主要画面，ui_icon 不得退成 emoji，成功生成的资产不得主动换成占位或代码简图。
- **设计层级保留约束**: 先完整保留 `design.md` 已纳入首版的页面、功能、状态和恢复动作映射，再列 3-5 个视觉实现锚点：默认首屏构图、关键视觉或资产、跨页面组件 / 状态语言和代表性动效；引用 `design.md` 对应章节，不重复改写视觉说明。任何视觉锚点都不得合并、删除或隐藏核心页面与功能，且 3-5 个视觉锚点不是功能交接上限，不得据此省略其他已纳入首版的页面与功能。
- **交互拓扑实现约束**: 原样承接 `design.md` 定义的核心对象、发现方式、动作入口、状态持久化和默认首屏职责，并把每项职责映射到真实组件或状态。
- **默认首屏视觉机制可见性**: `design.md` 声明的核心对象、主动作和即时反馈必须在默认入口初始 viewport 可见，不能全部等待点击、Sheet / Dialog 打开、路由切换或滚动后才出现；每个核心页面还要延续统一的对象组织、轮廓和材质语法。
- **首屏核心对象主图**: 默认入口主动作依赖可识别核心对象或动作载体时，主图任务必须包含并保护该对象，且和 HTML 信息 / 主操作共同构图；仅有环境、纹理、光照或其他氛围层不能代替该对象。
- **视觉机制交接**: 把 `design.md` 的核心业务对象、当前状态、主动作、持续入口、颜色角色、字体层级、轮廓、材质、景深、图像融合和动效映射到页面 / 组件 / 状态与实现 token；继续保留首屏闭合 viewport 算式、前三大视觉体块预算、safe area 唯一布局归属和滚动交接。
- **首屏与图片实现约束**: 把 `design.md` 的背景层、主体层、信息层、控制层和滚动交接层转成明确的容器、层叠、滚动和固定关系；把设备安全区、图像主体安全区和内容弹性安全区转成 safe-area padding、等比 object-fit / object-position、换行、minmax 和 overflow 约束；`image_mode` 为 code_native 时按代码原生视觉实现，为 image_supporting / image_led 时按资产真实比例、设计焦点和 `integration_mode` 接入图片，不能因 image_supporting 就自动缩小图片。不得把 `full_bleed_canvas` 缩成 hero / 卡片、把 `scene_overlay` 拆成图片与无关通用面板、把 `derived_backdrop` 换成无关图片、让 `surface_transition` 在主图末端突然切成无关 surface、把 `split_scene` 退成互不关联的两块容器、把 `pattern_field` 错当成带唯一焦点的拉伸壁纸，或把 `partial_foreground` 关进缩略图容器；要求主体完整显示时，容器比例必须与资产比例一致或使用完整显示策略，不得用 `object-fit: cover` 隐式裁掉主体。
- **弹层、遮罩与图标实现约束**: Sheet / Dialog / Drawer 的 Overlay 必须与可见前景内容共享开关和生命周期，不得留下孤立遮罩；上下文型底部抽屉默认无遮罩或使用不超过 `rgba(0,0,0,0.18)` 的轻遮罩，不得直接采用 `bg-black/80`。通用操作、导航和模式入口使用项目已安装且显式导入的统一图标组件库，优先 Lucide；不得依赖未交付的 icon font class、裸露英文 icon key 或 emoji。
- **App 壳层、横向尺寸与核心可见性约束**: 持久导航和同级页面共享有确定可用高度的 flex / grid 壳层；页面主体使用 `flex: 1; min-height: 0` 和唯一滚动区，禁止在只有 `min-height` 的父级下使用 `height: 100%`。单列 Grid 使用 `grid-template-columns: minmax(0, 1fr)` 或等价有界轨道，长文本、横滑条、图片和操作行所在子项使用 `min-width: 0; max-width: 100%`；只有设计稿指定的横滑容器允许 `scrollWidth > clientWidth`，App 根和全宽区域必须满足 `scrollWidth === clientWidth`。在最短默认态、最长结果态和最小支持宽度下，验证底部导航贴合容器底边、主按钮矩形完整且互不重叠；必需主图同时满足 `naturalWidth > 0`、槽位宽高非零且可见矩形与 viewport 相交，缩略图成功不能替代主图验收。
- **降级边界**: 仅允许非核心体验降级；核心能力不得降成静态演示。

## 3. 页面-状态-数据映射
- 按 `design.md` 的页面清单逐页建立状态、实体和关键动作映射。
- 对每个核心业务对象建立 ViewModel 契约，写清 required 字段、缺失字段策略、对象身份和下游最小完整性；无结构化对象时写 无。

## 4. 关键页面动作契约
- 按 `design.md` 的核心功能与主要动作逐条实现：触发页面、输入、处理、结果反馈、失败和空态都必须明确；涉及实时数据、公开目录、开放知识检索、大体量或完整性无法验证且需要按需补全的稳定知识、多人共享状态或媒体 / AI 转换时，必须有对应运行时调用、服务端处理或真实能力返回结果。
- 每个核心动作必须补齐前置条件、状态变化、持久化 / 能力副作用、成功状态、失败状态和禁止状态；返回、重试、跳过、重新开始、退出等恢复动作不得进入白屏、永久 loading、空详情或不可返回状态。
- 每个核心入口动作必须写清从用户点击 / 输入 / 选择到最终页面分支或结果区渲染的状态链路；页面模式、流程阶段、播放状态、详情状态等必须有单一 render-driving state，禁止只更新不参与渲染的影子字段。
- 对搜索、筛选、保存、发送、提交、统计、推荐等动作，必须补齐最小 journey：搜索命中 / 无结果 / 清空，保存后重新读到，提交校验失败显示原因，成功 / 失败 / 返回后 submitting、sending、loading 状态复位；统计指标必须写清唯一 source of truth 或同步规则、业务事件、对象、分子 / 分母和直接证据，代理信号不得命名成准确率、完成率或掌握度等业务结果。
- 对收藏、加入、报名、排队、取号、提交、资格校验、人数 / 年龄 / 性别 / 容量 / 状态限制、重复点击或幂等要求，最终改变数据的 handler / service / DB 写入必须执行校验并给出失败反馈；列表筛选、标签展示、条件说明或禁用文案不能替代最终动作校验。
- 对分配全局序号、扣减库存 / 名额、增加成员 / 计数等共享写入，必须使用当前能力真实支持的原子更新或冲突保护，并在写入失败时阻止成功反馈。
- 对搜索框、筛选框、联想输入、对象 / 地点 / 类目等用户连续输入，必须采用显式提交或 500-1000ms debounce、最小输入长度、single-flight / 取消旧请求策略，并写清 loading / empty / error 状态；远程结果进入本地过滤前必须 normalize，避免有效结果被过严 substring 或 key/label 比较清空。
- 对调用 LLM / AI_STREAM_CHAT / IMAGEGEN / MUSICGEN / WEB_SEARCH / WEB_SEARCH_SERVICE / VLLM / ASR / MEDIA 上传等可能耗时的动作，必须补齐 in_progress UI：显示“搜索中 / 生成中 / 加载中 / 识别中 / 上传中”等文案或骨架占位，保留输入和上下文，防重复触发，必要时提供取消 / 返回边界，失败后可重试；进度不可得时也不能静默空白。
- 对长时间语音、会议记录、实时字幕、连续听写、播放计时、游戏循环或动画计时，必须有“启动 -> 持续推进 -> 暂停 / 停止 -> 完成 / 恢复”的单一 render-driving state；单次回调、静态初始值或按钮反馈不能替代连续过程。
- 移动端长表单和连续控件必须保证能滚动到全部核心输入和底部主按钮；预算、价格、人数、时间等滑条 / 区间控件必须有明确当前值、拖动或等价输入反馈，不能被固定层、弹层或装饰图遮挡。
- 对动态文本、动画画面、沉浸式输出、核心结果区、主操作入口等核心输出或核心 CTA，必须保证进入核心态后 0.5-1s 内用户能看到核心内容或可点击主按钮；固定底栏、悬浮面板、全屏层、overflow、z-index 不得遮挡核心输出或核心按钮；底部导航与底部操作栏必须声明互斥、上移或 safe-area 占位规则。

## 5. 动画与视觉实现映射
- 保留 `design.md` 的首屏视觉锚点、结果态表现、关键资产引用、媒介隐喻、跨页面视觉系统和代表性动效；重动画只允许做非核心降级。

## 6. 数据模型与存储策略
- 根据 `design.md` 的核心能力和数据来源判断核心实体、存储生命周期、共享/隔离边界和媒体资源可持续回放边界。
- 凡涉及保存、记录、历史、我的、收藏、作品、库存、申请、回复等，必须补齐保存读取闭环契约：create / update / read_list / read_detail / delete 或不可删除边界、业务身份关联、成功后在哪里重新看到、读取失败与空数据如何区分。
- `design.md` 明确需要展示关联对象计数或状态时，补齐一条关联统计保留契约：主对象是基础记录集合，关联数据只补充字段，零关联对象仍保留并显示明确的零值或未发生状态。

## 7. 性能与降级策略
- 控制图片、列表、动画、字体和重资源加载成本；加载失败、空数据和异常状态必须给出可见反馈，并不得伪装成核心成功结果。
